# 定时图片对账的用量准入

更新：2026-09-11。当前 Schema v21，本模块不新增数据库迁移、API、服务、连接池或供应商凭据。它把已有用量状态接到**日本 Worker 定时全量对账**的发起点，默认关闭；不控制上传、页面图片、图片域名或缓存，不是账户零费用保证。

## 为什么先接这个执行点

现有全量对账由日本 Go Worker 发往北京 Python，再读取 S3/R2 对象与副本。这个动作可能产生较多 LIST/读取请求，并非完成权利下架所必需。

比较了仅告警、由北京直接查询 Analytics、复用日本持久状态三种方式。仅告警没有实际削减请求；北京查询会复制令牌、增加外部请求，且可能受网络区域限制。采用已有日本 PostgreSQL 状态及三连接池，在发送跨区请求前执行准入；北京仍不直连数据库/Analytics。

这是完整额度控制链中的一个执行点，不代替上传自动联动、API/Next 动态停图、源站直连入口或边缘缓存控制。另已开发[手动跨区上传控制](./MEDIA_UPLOAD_CONTROL.md)及[授权队列/后台页面](./MEDIA_UPLOAD_QUEUE.md)，具备独立可信回执。新增[逐操作上传准入](./MEDIA_UPLOAD_ADMISSION.md)复用 TaskGuard，在北京持久化系统暂停；本定时扫描准入或用量复核都不能隐式恢复上传。

## 配置

默认：`MEDIA_RECONCILE_USAGE_GUARD=off`。仅日本 Worker 配置，根级与日本模板均默认 off，北京/API/前端没有此配置或额外 Analytics 凭据。

后续确认供应商与观察状态、完成测试后，可显式配置：

```dotenv
MEDIA_USAGE_MONITOR_MODE=observe
MEDIA_RECONCILE_ENABLED=true
MEDIA_RECONCILE_USAGE_GUARD=enforce
```

还须提供观察器原有的明确账户、账期、15 分钟默认查询间隔和受限 Analytics token；本轮没有填写真实凭据或启用观察。`enforce` 必须与 Japan、observe、启用对账同时使用，错误值/缺少依赖拒绝启动，环境检查器也拒绝矛盾组合。`observe` 本身仍不会隐式启用准入。

所有日本实例必须升级、使用相同账户/账期/策略与开关；混跑旧实例会绕过扫描准入，不能把单实例测试当作跨实例保证。

## 实际流程

```text
每分钟调度（仅 enforce 模式）
  → 从现有 PG 读取状态，核对 Worker 配置摘要与有效期
  → 不通过：记录受限日志/私有指标，不创建对账运行，不发 HTTP
  → 通过：按数据库原有每日间隔领取、生成库存快照
  → 再读取并核对用量（避免等待库存/锁期间过期）
      不通过：运行记 failed / usage_guard_denied，不发 HTTP
      通过：真实 Go → 北京 Python 对账 → 原有严格结果核对/完成流程
```

Guard off 时保留原调度间隔，无新增准入读取。Enforce 时每分钟只做本地状态/到期检查，并不是每分钟扫描 S3。数据库仍用 advisory lock 和锁后新快照防止多个 Worker 同时领取完整扫描。

## 放行与拒绝

| 条件 | 行为 |
| --- | --- |
| 同账户/账期/策略的有效 low_estimate，或 70% warning | 可发起该次定时扫描，不代表免费额度充足 |
| A/B 任一高水位达到 85%，或更早触及自定义预留 | 拒绝新扫描；用 uint64 整数重新计算，不只相信低风险标签 |
| 持久复核/停用建议、未知状态/建议 | 拒绝，不自动清除标记 |
| 数据库读失败/超时/取消、未初始化、配置摘要变化 | 拒绝，不缓存或复用此前放行结果 |
| 查询截至时间或接收时间超过 30 分钟默认上限、未来时间、账期失效 | 拒绝；数据库读取结束后重新取时钟，等待时间不豁免 |
| 新账期尚无统计、切换后仍有复核标记 | 拒绝；只有新有效统计且已通过原有观察复核后才重新评估扫描 |

每次读状态最多 2 秒；库存准备最多 5 秒；创建运行后的拒绝留痕最多 3 秒。网络查询不持 PostgreSQL 锁/事务。不新增 Analytics 查询，仍只由原观察器查询。

## 延期、留痕与恢复边界

- 第一次拒绝没有实际运行，不伪造空对象报告或 completed；记录 `media_reconciliation_usage_deferred` 和有限 stage，不写账户/凭据/原始数据库错误。
- 库存准备后第二次拒绝保留该运行，记 failed/`usage_guard_denied`。仅此失败码不消耗每日扫描间隔；下一分钟可以重新评估。普通网络/报告失败仍遵守原间隔，不能无限快速重试。
- 写拒绝回执失败会保留原 running 证据并记录失败，不返回完成，也不发出 HTTP；需核对遗留运行，不手改审计制造成功。
- 未初始化/临时状态不可读后得到新有效状态，可自动重新评估定时扫描；已有 review/stop 标记不会被准入代码修改。普通复核和账期切换仍**不等于上传或图片恢复授权**。
- 已发出的请求不会被该两次检查原子撤销；检查后状态仍可能变化，Analytics 也存在延迟。因此当前保证是每次发起前的有界检查，不是供应商总操作数硬上限。
- 手工 Python CLI、直接调用受签名保护的对账端点、其他上传器不在此门禁范围；不能用这个开关宣称它们已停止。

## 保留的必要服务

权利下架/逐对象删除、缓存清理 outbox、账号与邮件、审核、历史归档、数据库/默认图每日检查不调用这个准入。每日检查只读取 PostgreSQL 发布状态并请求公开站内两张固定本地默认图，不遍历 R2 对象或访问资料记录中的图片 URL；为它增加 R2 用量闸门会反而隐藏完整性告警。Go→Python 测试验证：扫描门禁处于拒绝状态时，真实本地签名删除仍能完成。

必要操作仍可能消耗供应商请求，需要保留预算。不会为了少请求关闭权利处理，也不隐藏“对账过旧/从未完成”的原有告警。

## 私有指标和告警

在原 Worker Bearer 保护的 `/metrics` 输出，无新增监听端口：

- `self_deepsearch_media_reconcile_usage_guard_enabled`：该实例是否接入准入。
- `..._blocked`：最近检查拒绝，或检查缺失、超过 2 分钟、时钟倒退；不代表所有媒体已停止。
- `..._checks_total{outcome="allowed|blocked|unavailable"}`：有界三个结果的进程级计数，包含两次检查，不当作任务数。
- `..._last_check_timestamp_seconds`：最近实际准入检查时间。

新增 `PlatformMediaReconciliationAdmissionPaused`，持续 5 分钟 warning。指标抓取不重新做准入/查询供应商；不会让扫描暂停阻断独立 Worker readiness。进程重启会清空这些计数，但判断仍读取持久 PG 状态，不继承内存中的放行。

## 升级与验证

1. 先完成现有 Schema v21 迁移/受限账号检查。此功能无需新迁移，新增失败码沿用既有审计字段。
2. 升级所有日本 Worker、配置模板、环境检查器和监控规则；保留 off，先验证真实观察状态/时钟/供应商延迟。无需因本模块重建 API/前端/北京服务。
3. 在专用一次性 PostgreSQL 16 库执行扩展后的 `TestPostgresMediaUsageStateContract` 和 `TestPostgresReconciliationScheduleContract`：前者验证受限读取/失败/重启锁存/配置不符拒绝，后者验证真实并发领取及拒绝后不消耗日间隔、普通失败仍限频、原证据不被覆盖。沿用各自原有回环库/确认环境变量；无配置时 SKIP，不算验收。
4. 显式启用后验证缺失/高风险拒绝时北京无对账请求、必要删除不中断、低风险重新评估、私有指标和新旧告警；在日本 2C4G 限额下核对一分钟检查成本。
5. 回退旧 Worker 或切回 off 会移除这项扫描准入。应先关闭自动对账调度并记录操作，保留观察器/审计，不通过删状态/清高水位恢复。off 不是账期或风险复核。

本轮仅本地开发/测试，真实 SQL、供应商和两地运行验证仍未完成。可复跑结果见[验证证据](./evidence/release-a-media-task-admission-2026-09-11.md)。
