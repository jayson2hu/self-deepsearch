DELIVERY / 03

从明确问题，到完整体验。

先建立可复核的基线与代表页，再分批覆盖全部页面。每一批同时验收视觉、任务流程、移动体验和可靠性。

17–26人日估算 · 依范围与 API 配合调整
001–2 人日 / 基线

页面与任务盘点

整理现有界面、角色权限、性能基线与核心操作路径；明确真实问题。

交付：覆盖表、问题清单、基线证据

013–4 人日 / P0 + 视觉

先修问题，再立规范

纠正文案与错误态，改善密码确认和手机入口；建立五类样板与基础控件。

交付：首批修复、双端样板、设计变量

024–6 人日 / 公开站

串起发现与留存

优化首页、三类搜索、资料详情、关联浏览与收藏关注，保持查阅上下文。

交付：核心公开流程与完整页面状态

035–7 人日 / 后台

围绕任务组织工作

采集工作台、权限导航、真实分页、关联对象选择、字段差异审核。

交付：核心运营流程与所需接口

043–5 人日 / 质量

覆盖边界与低频页面

请求去重、慢网反馈、无障碍、公开站双主题、图片规则和视觉回归。

交付：性能对比、质量报告、完整覆盖

051–2 人日 / 验收

用真实流程验收

从查询到返回、从收取到核对，逐一验证关键任务并登记剩余依赖。

交付：实际截图、测试记录与回退说明

审查与首批修复已完成；后续全站改版按计划推进。
