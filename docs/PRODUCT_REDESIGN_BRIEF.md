## 1. 设计要达成的结果

让成年用户在手机上也能快速找到目标资料、判断资料依据、完成收藏或关注，并在之后容易找回；让运营人员能以可持续的成本维护这些资料。

本任务书以“可靠查询优先、关联浏览辅助”为推荐候选方案。它尚未替代原规划的浏览优先定位。不要直接把本文的候选方案视为已确认需求，也不要先把所有候选功能做成高保真页面。

设计时继续使用现有作品、人物、厂牌、审核版本、账号和媒体能力。视频资源、社交、人脸识别、用户文件上传以及本期广告联盟不进入范围。

## 3. 候选信息架构

公开站建议采用以下入口。URL 是设计用途描述；现有详情地址尽量保持稳定，不能因导航简化破坏外部链接。

```text
公开站
├─ 首页：搜索 + 一组主要内容 + 一个继续浏览入口
├─ 搜索：作品；后续可扩展人物、厂牌结果
├─ 浏览：最新发行 / 最近收录 / 有足够数据时的热门
├─ 人物：目录 → 资料 → 关联作品
├─ 我的：关注更新 / 收藏 / 关注人物 / 历史与偏好 / 反馈 / 设置
└─ 说明：关于资料 / 隐私说明 / 使用说明 / 纠错与权利联系

运营后台
├─ 我的待办：待核验 / 退回 / 待审核 / 待发布
├─ 资料：检索 / 编辑 / 来源 / 预览 / 版本差异
├─ 图片：资产 / 处理状态 / 登记与替换
├─ 反馈与权利请求
└─ 管理：用户权限 / 系统状态 / 用量与上传控制 / 审计
```

桌面主导航控制在少量稳定入口，厂牌仍可从作品详情、搜索和浏览进入。手机常驻可见搜索与“我的”，其他导航可展开；是否使用底部导航由原型测试决定。不能把手机的搜索完全隐藏。

## 4. 核心页面设计要求

### 4.1 首页

首屏只需要帮助用户理解站点范围、开始查询或选择一个明确的浏览入口。

- 标题候选：“查找作品与人物公开资料”。搜索提示同时说明番号、标题、人物；在未扩展多实体搜索时注明人物名用于查找关联作品。
- “仅公开资料、18+”保持简短可见，完整说明放在说明页。测试环境标记按真实部署环境展示。
- 查询优先方案只突出一组主要内容，例如最新发行；推荐区以真实理由区分，不同时用多个相近榜单占满首页。
- 未登录关注提示保持紧凑；已登录但未关注时给人物入口；已有关注且有更新时突出更新。
- 热门无可靠数据则隐藏该区块；编辑推荐必须有编辑选择和理由，不随机填充。
- 未售广告占位按 D-02 决策处理，页面不显示“混排”“详情请求”“不加载第三方脚本”等内部说明。

需要同时出三种状态：全空目录、少量内容、较丰富内容。全空目录只给出一个准确的站点状态与下一步，不排列多块重复空提示。

### 4.2 搜索结果

保留关键词和筛选条件；开始新搜索时清除旧分页游标。编号精确匹配优先，存在多个版本时明确展示候选差异。

结果卡至少帮助用户确认：实体类型、番号或名称、标题、实际发行日期（未知要明确）、人物或厂牌，以及可公开的匹配依据。人物结果不伪装成作品卡。

首轮只提供数据确实支持的筛选，不因为设计稿有空间就增加标签、评分或不存在的数量。原有“下一页”可继续使用；需保留搜索状态和返回位置，再决定是否改为加载更多。

| 状态 | 用户应得到的反馈 |
| --- | --- |
| 输入为空 | 一句话示例与可直接开始输入的搜索框 |
| 格式或长度不合法 | 在输入旁指出要求，保留输入 |
| 有结果 | 明确匹配范围；可直接进入详情 |
| 无结果 | 说明未收录到匹配资料，提供改词、重置条件或人物入口 |
| 结果被个人偏好隐藏 | 说明过滤原因，并按 D-05 提供主动查看方式 |
| 服务不可用 | 保留输入和条件，提供重试，不能称为“没有资料” |
| 有重复/不同版本 | 展示多个候选和差异，不能擅自合并 |

### 4.3 作品详情

手机优先级如下，桌面可以使用左右分栏，但阅读顺序保持一致：

1. 可见搜索入口和必要的返回入口。
2. 番号、完整标题、复制番号、收藏。
3. 实际发行日期、人物链接、厂牌链接、核验摘要。
4. 主图；缺图时缩小无效图片空间，保留完整文字识别。
5. 资料摘要、可公开来源、字段缺失说明和纠错入口。
6. 可选精选图、存在且有数据支持的版本关系。
7. 带理由的相关作品。

信息主次：收藏为主要保存动作，人物/厂牌为继续浏览，纠错和不感兴趣为次要动作。不要把这几种意图全部合成一个“登录后……”按钮。复制番号不要求登录，并有明确成功反馈。

公开可信信息候选文案：“发行日期来自公开发行目录，最近核验于 YYYY-MM-DD”。核验日期只对真实完成核验的字段生效；系统更新时间不能冒充核验时间。“资料完整”也不能与“资料准确”混为一谈。

### 4.4 人物与厂牌详情

人物页优先名称、原文/别名、关注和关联作品；可选身体参数折叠或后置。提供来源说明与纠错；没有已核验字段时不通过堆“待补充”撑满首屏。

关联作品可按实际发行与本站收录切换，但这两种排序必须有明确解释。分页需要 API 支持；达到查询上限时不能伪装成完整列表。厂牌页遵循同样的排序、分页和来源规则。

### 4.5 账号、注册与关注更新

账号操作围绕任务连续性设计：

```text
作品详情 → 点击收藏 → 登录或注册 → 返回同一作品 → 完成/确认收藏
人物详情 → 点击关注 → 登录或注册 → 返回同一人物 → 看到关注成功与更新入口
```

统一保留站内返回目标，登录/注册/重置切换不丢失目标。返回目标失效时说明原因；纠错、隐藏和关闭账号不自动执行。弹窗方案必须同时设计键盘焦点与独立登录页面，不能以弹窗替代可访问入口。

验证码步骤需包括发送成功、倒计时、重发、修改邮箱、过期、尝试过多和服务故障。重发与限流遵守后端规则，不降低原安全要求。密码规则提前说明，支持密码管理器和粘贴。

“我的”优先展示关注更新与收藏，不让“关闭账号”成为设置页唯一的实际能力。首期先提供稳定的更新入口；新增未读状态前明确如何记录已读，避免每次浏览自动修改一批状态。

隐私说明在注册前可访问；历史开关与保留策略按 D-03 的最终决定实现。文案应准确区分“停止记录新历史”“隐藏已有历史”“关闭账号”以及其他已明确支持的数据操作。

### 4.6 纠错与权利联系

资料页纠错自动关联对象，用户只需选择字段、描述问题并可选提供来源链接。普通反馈继续登录后人工审核，提交后提供反馈记录入口。

公开状态使用“已提交、核对中、已采纳、未采纳”等中文含义；“已采纳”与“资料已发布修正”如有时间差，要分别表达。用户可见的回复和内部审核理由不能直接混用。

权利联系在退出账号时仍可达。站点缺少真实联系渠道时，测试环境可以如实显示未配置；开放真实用户前必须提供有效渠道，并按已有下架流程处理。

### 4.7 运营工作台

首屏优先“我接下来该处理什么”：我的待办、退回原因、临近响应期限、已通过待发布。严重系统故障保留醒目摘要，详细数据库、存储和备份信息进入管理区域。

资料编辑用名称搜索选择人物与厂牌，显示必要的同名辨认信息，实际提交仍使用稳定 ID。展示当前状态、最近版本、来源摘要和可执行动作；同时提供资料预览与字段前后对比，原始 JSON 只作为高级信息。

发布前使用页面内确认，集中展示对象、公开地址、内容摘要、来源和影响；不连续弹出多个只带文本输入的原生提示框。提交后明确“已提交发布，公开可见状态待确认”或真实的完成状态，不能把异步处理统一显示为全部完成。

独立草稿保存是候选新增能力，实施前检查后端生命周期。编辑、提交、异人审核、发布、隐藏和权利下架仍分别管理，界面简化不能跳过审核。

媒体首轮改进集中于流程指引、所属资料名称和任务状态，不默认增加网页直接上传原始图片的路径。

## 5. 视觉与交互共同规则

风格方向：安静、可阅读、像持续维护的资料库。可以沿用现有品牌和色彩，先用信息层级改善体验。

| 项目 | 设计要求 |
| --- | --- |
| 字体 | 手机主要正文建议从 16 px 起验证；辅助信息不能承担唯一的关键解释 |
| 操作尺寸 | 主要触控目标建议至少 44 × 44 CSS px；全站按 WCAG 2.2 检查目标尺寸及适用例外 |
| 焦点 | 键盘可见焦点；搜索输入、筛选、弹窗、错误返回均可操作 |
| 卡片 | 作品/人物类型可辨认；普通列表不展示容易误解的排名；长标题可阅读 |
| 缺图 | 保留番号/名称和关键字段；缺图说明简洁，不出现巨大无信息占位 |
| 状态 | 统一正常、加载、无数据、筛选为空、错误、下架、缺图的说明和下一步 |
| 手机布局 | 至少检查 320、390、768 px 与桌面 1440 px；普通内容无整页横向滚动 |
| 反馈 | 收藏、关注、复制有明确成功/失败提示；危险操作说明后果；可撤销操作给撤销入口 |
| 个性化 | 同页共享偏好状态；加载与失败不产生互相矛盾的过滤结果 |
| 性能 | 保留图片尺寸、懒加载与默认图能力；目标环境继续执行已有性能门槛 |

44 px 和 16 px 是本产品建议值，不是对 WCAG 的逐项等同声明。规范依据与解释见[评审参考资料](./PRODUCT_REVIEW_2026-09-16.md#82-外部依据)。

## 6. 原型必须覆盖的状态与数据

至少准备：正常有图、只有默认图、长标题、多人物、同名人物、同番号不同版本、日期缺失、无结果、服务失败、隐藏偏好、资料下架、未登录、有关注无更新、有更新、验证码过期、来源不可公开。

内容样本必须能说明真实任务，不能以几十条相同标题填充原型。未来使用真实图片做视觉检查前，应已具备相应审核与展示条件；原型阶段可使用合成或允许使用的素材。

设计交付物包括：

1. D-01 至 D-09 的决策记录，包括目标搜索市场和内容索引范围。
2. 手机和桌面的首页、搜索、作品详情、人物详情、登录续接、“我的”、纠错与运营任务页。
3. 四条可点击任务流程：查找、收藏/关注续接、纠错、录入到发布。
4. 核心组件及状态表、文案表、公开字段与内部字段边界。
5. 对现有 URL、API、数据策略的变更列表和分期说明。
6. 原版与候选版的任务测试记录，以及据此作出的修改。

## 7. 设计评审通过条件

以下是建议目标，尚未测试。未达标时先修正关键任务，不以视觉风格喜好代替验收。

- 参与测试的成年用户能说明站点提供什么，并完成主要查找任务；首轮建议目标为至少 80% 正确完成，无主持人提示。
- 核心查找任务建议在 30 秒内找到正确详情并确认两个关键字段；内容未知时，正确识别“未知”也可作为任务设计的一部分。
- 从详情发起收藏/关注，完成登录后不需要再次搜索目标；成功、取消、失败和目标下架均有确定结果。
- 用户能解释“清除可见历史”与“彻底删除”的区别，并找到完整说明。
- 手机详情有直接搜索入口；默认图与长标题场景仍能快速识别目标。
- 运营人员无需查数据库或手写 UUID 建立常见关联，能够读懂版本变化、下一步和异人审核要求。
- 所有新增可见字段有数据来源；接口尚不具备的能力明确标为后续，不能当成已完成。

小样本通过只允许进入下一步试用，不证明市场需求、线上留存或商业化成立。上线仍须独立完成[现有发布门槛](./RELEASE_A_READINESS.md)。

## 8. SEO 必须进入设计交付

SEO 不是页面完成后补一组关键词。详情、列表、关联路径和状态设计阶段就要交付以下内容；完整规则见 [SEO 方案](./PRODUCT_SEO_PLAN.md)。

- 每种页面的搜索意图、目标用户与独立价值；一个真实实体的别名尽量在同一主页面解释。
- title、描述、H1、来源摘要与面包屑的模板，包含长标题、日期未知、缺图、同名及多版本。
- 可公开、可索引、可提交 sitemap 的矩阵，以及图片和搜索预览的展示范围。
- 正式域名和稳定 URL、旧址跳转、可抓取内链、合法分页与筛选参数的行为。
- 正常、404、下架、暂时故障的 HTTP 与页面状态，不用视觉空状态代替正确响应。
