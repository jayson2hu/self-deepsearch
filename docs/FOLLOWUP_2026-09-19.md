## FU-03 实施设计

保留 schema 27 的单批 1,000 条约束，不硬抬限制。每轮用同一只读目标游标快照稳定续取 1,000 条，逐批记录 scan/audit，整轮事务提交；任意后续批失败或取消，所有批次和问题变更回滚，重试整轮（不提供跨失败断点恢复）。扫描响应新增整轮批数/总扫描数/总问题数/轮次 ID，历史列表明确标为批次，不能将最后一批数量冒充全部。

每日巡检在 API 进程中运行，默认关闭，显式配置 `SEO_DAILY_SCAN_ENABLED=true` 与 `SEO_DAILY_SCAN_ACTOR_ID=<active admin/owner UUID>` 后启用；启动检查并每分钟重试，数据库锁与已完成记录保证上海自然日每日至多一轮成功。配置负责人失效则拒绝执行；自动审计使用 system 来源，不伪装人工点击。手动限时 10 秒，每日轮次限时 2 分钟；超时回滚、日志报警并重试，不能将超预算大规模巡检标记完成。无外部 HTTP 抓取、无自动关单或索引资格变更。

真实受限角色验收：2,184 个目标分 3 批扫描，3 份审计，全轮约 3.73 秒；同日再次调度不新增、次日可运行、并发锁拒绝重叠、取消生效、无权限负责人拒绝。隔离库向第二批注入异常后，第一批及全部变更均回滚；移除故障后同日可重新扫描全部目标。API 全包回归与 ops lint/build 通过；没有把生产大规模压力或外部 HTTP 抓取算作通过。
