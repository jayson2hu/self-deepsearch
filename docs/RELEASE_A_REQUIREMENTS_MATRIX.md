# Release A 需求与验收矩阵

更新时间：2026-09-12（Asia/Shanghai）  
适用范围：作品与公开人物资料展示测试网站。自动采集属于 Release B，广告联盟属于 Release C，头像/人脸识别不在当前路线内。

## 1. 使用方式

本文件是 Release A 的需求状态权威入口，用来回答三个不同问题：

- 产品是否仍符合最初目标；
- 当前仓库是否已经实现对应代码和离线验证；
- 哪些事项必须在真实 PostgreSQL、邮件、对象存储、Cloudflare 或目标服务器上完成后才能放行。

状态定义：

| 状态 | 含义 |
| --- | --- |
| 本地完成 | 代码、合同和不依赖真实基础设施的验证已完成 |
| 条件完成 | 本地实现完成，但必须在目标环境执行真实联调 |
| 后续版本 | 已明确不属于 Release A，不得为凑完成度提前启用 |
| 待确认 | 缺少产品口径，不能擅自实现或宣称可计算 |

“本地完成”与“条件完成”都不等于公网可用。真实放行结论仍以 [Release A 发布就绪审计](./RELEASE_A_READINESS.md)和一次具体的[上线执行记录](./RELEASE_A_GO_LIVE_RECORD.md)为准。

## 3. 运营录入边界

Release A 的真实实现口径如下，避免把三种入口混称为“都支持 CSV”：

| 数据 | Release A 入口 | 审核与发布 |
| --- | --- | --- |
| 作品 | 后台单条录入；作品 CSV 预检、错误下载和幂等批次导入 | 进入 revision/review，必须由不同运营账号审核发布 |
| 人物 | 后台单条录入和后续修订 | 进入 revision/review，必须由不同运营账号审核发布 |
| 厂牌 | 后台单条录入和后续修订 | 进入 revision/review，必须由不同运营账号审核发布 |
| 图片 | 北京 `media-python` 处理本地文件并生成 manifest；后台导入并核对 manifest | admin/owner 核对来源、权利、实体关联和北京副本后登记；不从 URL 下载 |

人物 CSV、厂牌 CSV 和让管理员手填图片对象元数据都不是 Release A 门槛。以后若实际录入量证明有需要，应复用作品批次的预检、幂等、错误导出和审核合同，不能增加绕过审核的快捷入口。

## 4. 当前未关闭事项

2026-09-12：本机 Ubuntu Docker 已完成 PostgreSQL 16 迁移/权限、API 仓储和 Worker 并发合同、Mailpit 账号/邀请及异人审核发布、本地备份恢复。见[Ubuntu 验收记录](./evidence/release-a-ubuntu-acceptance-2026-09-12.md)。以下清单指目标环境剩余验收，不能继续把已通过的本机测试写成未执行；R2/Cloudflare、两地部署与公网尚未通过。

### 4.1 只缺真实环境验收

- 日本 PostgreSQL 16 的 Schema v21 fresh/upgrade、运行账号、SQL 并发合同、受控 fixture 和恢复；
- Mailpit/SMTP 的注册、重置、关闭账号、邀请和旧 session 失效；
- 两个不同运营账号的录入、领取/改派、异人审核、发布、番号搜索、回滚/隐藏和权利下架；
- 双 bucket、北京副本、manifest、主图替换、30 天保留、物理删除、Cloudflare purge、对账和容量保护；
- 目标服务器 Compose/镜像、最终域名、TLS、Turnstile、后台网络限制、告警通知、视觉、性能和资源使用。

### 4.2 当前不应继续写成 Release A 代码缺口

- 自动采集连接器、来源域名和解析脚本：Release B；
- X/其他官方账号自动采集与公开展示：后续人物资料增强；
- 广告联盟、倒计时、弹窗、广告结算与收益优化：Release C；
- 头像识别、人脸搜索或识别 API：不做；
- 匿名搜索结果点击率：统计口径尚未确认，当前为待确认产品指标，不得伪造实现状态；
- 发现流同人物/厂牌重复抑制：属于真实目录上线后的质量调优，不影响已确认的作品/人物 4:1 核心合同。

## 5. 当前结论

- 初始产品方向与当前实现保持一致：资料展示、作品发现、番号搜索、人工审核、可选账号、图片兜底和广告占位；没有演变成资源站、头像识别服务、自动采集站或已接广告联盟的网站。
- Release A 没有已确认且必须在无外部依赖条件下继续补写的 P0 业务功能。当前本地代码与部署包为 `conditional-go`，下一阶段的有效工作是进入隔离真实环境联调并修复联调发现的问题。
- 在 PostgreSQL、邮件、R2/Cloudflare、目标服务器和最终域名证据完成前，完整 Release A 与公网开放继续为 `no-go`。
