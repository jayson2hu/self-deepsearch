- 新增 `/account`“我的账号”总入口，汇总收藏、关注、推荐偏好、浏览历史、反馈和账号设置；主导航“我的”和登录账号菜单均先到该入口。
- 总入口明确不提供未读数量、新消息角标或虚构计数。每个子页面只展示既有接口能证明的记录和状态。
- 收藏/关注页补充空状态去向、服务故障重试链接，以及“取消操作在对应详情页完成”的准确说明；不新增或修改既有关系模型。

- 首页关注区从“新作品/动态”改为“已发布作品”，避免把旧发行但新收录的资料、未读通知和真正新发行混为一谈。
- 我的反馈将真实枚举映射为中文：`pending → 已收到`、`reviewing → 处理中`、`accepted → 已采纳`、`rejected → 未采纳`、`closed → 已结束`；反馈类型也使用中文名称。
- 用户反馈页只显示本人提交内容、公开状态和提交时间。公共 API 仍不返回审核人、审核时间或审计 reason；页面明确内部审核备注和其他用户反馈不会下发。
- 反馈提交成功后提供“查看我的反馈状态”去向。登录续接仍仅用于收藏/关注的显式二次确认，不保存反馈文本，不在登录后自动提交反馈。
- 没有新增三实体反馈模型、未读系统、多设备通知、邮件推送、数据库迁移或数据清理。

## 真实 PostgreSQL 反馈隔离结果

一次性 PostgreSQL 16、Schema v21、受限 `platform_api_login` 创建两个合成用户和两条反馈：

- 用户 A 的 `ListFeedback` 只返回 A 的反馈，用户 B 的列表只返回 B 的反馈。
- A 的反馈经内部 reason“内部审核理由不得下发给用户”处理为 accepted；该 reason 只存在于 `audit.audit_logs`。
- A 的用户列表只得到 `accepted` 枚举及原提交内容，`Reviewer`、`ReviewedAt`、`Submitter` 等审核侧字段保持空值，没有跨用户或内部备注泄漏。

容器和合成数据在测试后自动停止并删除；未连接长期或生产数据库。
