# 幕鉴前端全面优化计划

日期：2026-09-22。状态：**现状审查与规划已完成，首批页面修复已通过浏览器验证，整体改版分阶段推进**。本文件回应“全面优化前端、审美要好、兼顾用户体验之外的质量”的需求。

核心范围：公开站 `apps/display-web` 的 25 个 page 路由模板，运营后台 `apps/ops-web` 的 26 个 page 路由模板。动态路由算一个模板；采集项目的离线演示与旧联调预览是辅助工具，优先复用正式后台的验收能力，避免出现三套竞争的操作入口。

配套：[视觉方向与实施路线预览](frontend-optimization/index.html)。这是可交互的设计说明，使用示意数据，不连接业务接口，不代表已完成前端改版。

## 1. 要达到的效果

公开站定位为有辨识度的资料索引：用户迅速找到目标，判断资料是否相符，继续浏览或收藏。运营后台定位为清楚、可靠的工作台：用户知道先处理什么、当前对象处于什么状态、操作会产生什么结果。

优化同时覆盖八个方面：

| 维度 | 目标 | 交付证据 |
| --- | --- | --- |
| 视觉与品牌 | 有统一的字体、配色、节奏、图像规则；内容主次清晰，稀疏数据也完整 | 代表页设计、设计变量、桌面/手机/深浅主题对比 |
| 信息架构 | 导航按用户任务组织，入口与权限一致 | 导航树、角色矩阵、页面覆盖表 |
| 操作效率 | 查询、详情、返回、连续处理保持上下文 | 任务路径、操作次数与任务时间前后对比 |
| 内容与文案 | 说明实际能力，错误与空数据准确区分，技术证据按需展示 | 文案表、全状态组件样本 |
| 移动与无障碍 | 手机可完成主要任务，键盘、读屏和缩放可用 | 视口/键盘/焦点/对比度检查 |
| 性能与稳定性 | 主要内容及时出现，交互有反馈，失败可恢复 | 受控性能基线、请求数量、故障测试 |
| 发现与留存 | 搜索、关联资料、收藏关注形成连贯路径，广告不干扰查询 | 用户任务验证、已有指标的准确口径 |
| 工程与维护 | 组件可复用、变更可回归、分批可发布和回退 | 组件目录、视觉回归、实施与验收记录 |

本轮新计划沿用已有产品事实：待审核采集数据继续留在后台；公开站只展示已发布资料；图片使用已获准资产和既有媒体接口；私人状态不进入公共缓存。此前[数据接收与后台验收](COLLECTOR_E2E_ACCEPTANCE.md)通过的接口与数据隔离规则是回归基线。

## 3. 视觉方向：当代资料馆与专业工作台

### 3.1 公开站

推荐“当代资料馆”的方向：纸白背景、深墨文字、少量朱砂强调色，清楚的编辑排版，资料内容成为主角。保留“幕鉴”名称及品牌识别，不额外引入装饰性吉祥物或大幅虚构内容图。

- 首页有一处有辨识度的查询主区；搜索与目录页采用紧凑页头，让结果尽早进入首屏。
- 作品卡优先呈现番号、标题及能区分对象的信息；普通列表取消排名序号。
- 人物卡采用稳定头像比例；无头像时使用低对比的姓名/图形占位，不生成仿真人物头像补空缺。
- 大标题可局部使用本地衬线字体表达编辑气质；正文、数据和控件继续使用清晰的系统无衬线字体，不依赖外部字体请求。
- 图片稀疏时主动调整构图和信息密度，避免整页重复大灰框；不为美观伪造资料、日期或热度。

### 3.2 运营后台

推荐浅灰工作区、深色分组导航、墨蓝主操作，状态用绿/琥珀/红表达。与公开站共享控件、间距和焦点规范，同时保持适合长时间工作的密度。

- 页面分“标题与主要动作、摘要与筛选、核心工作区、补充证据”四层。
- 默认舒适密度，熟练运营可选择紧凑密度；不以 9px 状态字或隐藏按钮换取整齐。
- 候选详情先显示姓名、来源、当前状态和下一步；UUID、hash、原始 JSON 收进可展开的技术证据区，并提供复制反馈。
- 表格适合桌面比较；手机按任务改为卡片。需要对照的复杂表格保留局部横向滚动，并给出明确提示。

### 3.3 设计规范初稿

| 项目 | 初稿规则 |
| --- | --- |
| 公开主色 | 朱砂 `#B63D32`；纸白 `#F5F3EE`；深墨 `#202824` |
| 后台操作色 | 墨蓝 `#245B72`；浅灰工作区；既有状态色另按语义校准 |
| 文字 | 公开正文 16px；后台正文/表格 14px，紧凑模式可 13px；重要辅助信息至少 12px |
| 标题 | 桌面主要标题 32–40px，手机 26–30px；分区标题 20–24px；具体按样板页微调 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64；以内容组关系决定间距 |
| 圆角/阴影 | 输入框约 8px、内容卡约 10–12px；阴影主要用于浮层，不给所有区块加立体效果 |
| 布局 | 内容最大宽度约 1200–1280px；后台复杂工作区可扩展；组件使用 minmax(0,1fr) 等防溢出约束 |
| 动效 | 状态过渡约 120–180ms；只帮助理解变化；尊重减少动态效果设置 |
| 图片 | 明确尺寸和裁切规则；缺图、失败、稀疏数据作为正式设计状态 |
| 移动操作 | 主操作采用至少 44×44 CSS px 的产品目标；主要任务不依赖横向滚动 |

上述颜色是设计候选。对指定色对的计算：白字/朱砂约 5.67:1，白字/墨蓝约 7.46:1，深墨/纸白约 13.62:1；仍须检查真实页面中的 disabled、hover、focus、状态底色及深色主题，不能把候选色计算当作全站无障碍认证。

视觉方向预览用于确认版式和气质；生产控件会通过真实资料、长文本、空态与双主题验证后落地。

## 4. 页面与流程优化

### A. 公开站

| 页面族 | 具体改动 | 用户完成的任务 |
| --- | --- | --- |
| 首页 | 统一三类搜索入口；缩短说明；最新发行/最近收录/人物入口有明确层次；减少首屏重复操作 | 知道能查什么并直接开始查询 |
| 搜索 | 专用搜索页头；类型切换保留关键词；输入、当前类型、结果区连续；错误只展示对应状态；合法别名能力用简短提示表达 | 判断命中对象并进入正确详情 |
| 目录 | 统一局部导航和本类型搜索；明确排序口径；保留游标、返回第一页和浏览位置 | 浏览多页且不迷失 |
| 作品详情 | 身份摘要与主操作前置；番号复制反馈；相关人物/厂牌清楚可点；图片和浏览统计降低竞争 | 确认资料、收藏、继续关联浏览 |
| 人物/厂牌详情 | 手机紧凑身份区；别名按需展开；有值字段优先；缺失说明集中；关联作品更早可达 | 区分同名对象并查关联作品 |
| 我的/收藏/关注/历史 | 一致子导航；列表内取消关系与恢复；历史按时间组织；登录与返回续接；事实性隐私说明贴近相关操作 | 管理个人资料与偏好 |
| 登录/注册/重置/邀请 | 一致表单、字段级错误、提交反馈、返回目标；密码可见切换及自动填充语义 | 一次完成账号操作并返回原任务 |
| 关于/隐私/反馈/不可用页 | 阅读宽度、目录/分组、简洁下一步；保留准确的状态和数据处理事实 | 理解产品并找到处理入口 |

不提供尚无接口支持的任意跳页、虚构总量、评分或推荐原因。新增过滤项先确认可用字段、权限与 API 合同。

### B. 运营后台

建议导航分组：**内容处理**（采集、目录、审核、冲突、反馈）、**发布运营**（推荐、广告、访问、SEO）、**资产与系统**（媒体、用量、权利、用户、审计、设置）。新建作品/人物/厂牌成为相应目录的主要动作。最终分组按角色任务验证，不能仅修改菜单名称而忽略旧链接。

| 页面族 | 具体改动 | 验收重点 |
| --- | --- | --- |
| 运营概览 | 按角色显示可行动待办；指标链接对应筛选；系统健康单独分区；未知与零区分 | editor 首屏聚焦内容任务，故障不显示假 0 |
| 采集验收 | 顶部少量真实摘要；默认人物候选；批次为标签/次级视图；手机卡片；筛选可分享、可恢复 | 手机首屏能搜索；每条详情入口不在屏外 |
| 候选详情 | 身份摘要、状态组、来源证据、技术详情分层；安全返回参数；上一条/下一条 | 连续核对不丢过滤与位置，不暗示可直接公开 |
| 资料目录 | 服务端搜索/过滤/分页；真实总量；可复用对象选择器 | 超过 200 条仍可完整查找；需要 API 配合 |
| 录入/编辑 | 基础字段、关联对象、来源分组；替代手填 UUID；就地校验；未保存提示；成功导航 | 错误可修复、输入不丢失 |
| CSV 导入 | 上传、预检、错误定位、结果与可下载错误文件形成连续步骤 | 行号与字段准确，重复提交/部分失败有明确反馈 |
| 版本/审核/冲突 | 字段级原值/新值/来源对照；未变内容折叠；原始 JSON 为高级视图 | 不读 JSON 即可判断变化；权限与独立审核规则保留 |
| 媒体/用量/上传/权利 | 状态与风险层级；任务进度、最近更新和失败恢复；危险操作明确对象与影响 | 真实执行结果反馈，不混淆排队与完成 |
| 用户/审计/统计/SEO/广告 | 共享筛选、列表、空态、时间范围、状态语义；图表附数据口径与表格替代 | 数量与列表同口径，敏感内容最小展示 |
| 推荐/站点设置 | 生效范围、当前值与待保存变化分组；操作反馈与权限一致 | 不把预览状态混同于已生效状态 |
| 登录/退出 | 统一表单与错误状态；会话过期保留可安全恢复的任务入口 | 退出清除私人状态，依赖故障不冒充身份失效 |
| 高风险确认 | 统一确认面板、遮挡密码输入、理由和错误保留；键盘与焦点行为 | 取消不写入、重复点击不重复提交、成功反馈准确 |

## 7. 验收标准

### 7.1 视觉质量

- 公开站与后台各有明确的视觉重心；页面首屏能识别主要任务，次级证据不占据主层级。
- 相同语义的按钮、状态、字段、空态、分页采用统一组件和词汇；主要文字不靠极小字号维持布局。
- 检查长中日文标题、多别名、无图、缺日期、稀疏资料、密集数据；合法素材与占位状态都形成完整设计。
- 公开站既有深浅主题覆盖正常、hover、focus、disabled、错误、弹窗，不只验证页面背景；后台首阶段以浅色工作区验收，新增后台深色模式不计入本估算。
- 使用“层级、排版、对齐、色彩与状态、内容适配”五项评审表逐项确认；保留改版前后截图和判断理由。美观由具体画面评审，不能只靠 Lighthouse 分数代表。

### 7.2 任务效率

必测任务：三类搜索进入正确对象；列表第二页→详情→原列表；游客收藏→登录→回到目标确认；候选关键词→详情→返回；连续核对多条；新建资料选择关联对象；版本变化确认；普通用户拒绝访问后台。

- 390×844 的公开查询和后台候选页首屏可找到搜索及首组有效内容。
- 手机不横向滚动即可完成主要查询、详情和返回操作；复杂证据表的局部滚动是明确例外。
- 状态、筛选、页码和返回目标可恢复；成功、失败和进行中都有准确反馈。
- 对连续核对、关联录入等高频任务，先测基线，再以操作次数和中位任务时间改善作为目标；初始目标约减少 25% 无效往返，未实测前不宣称达标。
- 条件允许时邀请 3–5 位目标使用者做任务测试；每轮至少 10 次关键任务执行，目标完成率 ≥90%。小样本结果只用于发现问题，不推断总体用户满意度。

### 7.3 响应式与无障碍

- 覆盖 320/390/768/1024/1440px，以及关键断点前后 1px；200% 缩放后主要内容和操作完整。
- 基于 WCAG 2.2 AA 检查文字对比度：普通文字至少 4.5:1，大字至少 3:1；图标/边框/焦点另按适用条款核对。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- WCAG 2.2 AA 最小指针目标要求为 24×24 CSS px 或满足列明例外；本项目对主要触控操作采用更高的 44×44 设计目标，两者不混为一个规范要求。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 跳过导航、可见焦点、表单错误关联、状态播报、弹窗初始焦点/约束/Escape/归还均有用例。
- 自动扫描无严重或致命问题，同时保留人工键盘/读屏检查；扫描结果不等于全站符合性认证。
- Chromium 全量核心流程，WebKit/Firefox 做导航、表单、弹窗和布局冒烟；具体浏览器版本记录在报告。

### 7.4 性能与可靠性

- 保留现有 LCP/CLS 探针与缓存合同，扩展搜索、人物详情、后台采集/目录；分别记录冷启动、预热、受限网络/CPU场景。
- Core Web Vitals 目标：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1。真实用户指标以第 75 百分位评价；本地脚本只报告实验室测量和交互代理指标，不冒充现场 INP。
- 先记录 JS/图片传输量、上游调用数、TTFB、任务反馈时间，再制定具体页面预算；同条件测试禁止无解释退化。每个代表场景至少 5 次采样并注明环境。
- 单次导航中可合并的身份/偏好请求去重；卸载取消、超时可重试；注销/切换账户清理私有请求缓存。
- 广告慢或失败不阻塞核心任务；标签页隐藏时停止周期轮询，恢复仅做必要刷新；保留过期、撤回、错误撤下约束。
- 不放松既有 301/400/503、canonical/noindex、发布/下架缓存失效、私人数据隔离规则。

### 7.5 数据、隐私与交付

- 真实采集数据继续只在后台验收；沿用 4,196 条/9 批次的实际 HTTP 投递与浏览器对账。
- 缺少后端能力的过滤、批量动作、计数明确登记依赖，不绘制假完成按钮。
- 访客统计增加浏览器网络断言：未同意、拒绝、撤回、GPC/DNT、存储故障等情形不发送 visitor_token；普通 PV 是否继续计数保持现有真实产品约定，文案准确。
- 每批完成构建、类型、lint、相关业务测试、截图差异与人工视觉检查；报告包含失败与修正记录。
- 形成实际变更文件、接口变更、迁移需求、验收结论、剩余问题与回退路径；不得以静态效果图替代真实流程验收。
