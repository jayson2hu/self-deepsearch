## 已确认的统计现状

正式产品已有详情客户端上报 `POST /api/v1/metrics/page-view`，按小时聚合作品/人物/厂牌 PV；详情展示近 30 天及累计浏览。热门作品支持近 7 天、30 天、累计排序。页面 GET/列表翻页不直接计数；未发布对象不接受公开计数。当前没有 UV 数据，不能从 PV 倒推真实人数；内部采集预览也不应混入正式流量。

“用户访问次数”的全站 PV/UV 或逐注册用户口径已向用户异步确认。当前先基于现有记录补充详情 PV、登录普通用户访问次数、去重注册用户数和热门排名，不增加匿名追踪标识。全站 UV 明确显示“暂未统计”，不能把去重注册用户数标为全站 UV。

## 访问统计设计与实现（TR-02）

- 入口：后台 `/traffic`，侧栏“访问统计”；仅 owner/admin 可见。接口 `GET /admin/v1/traffic?range=7d|30d|all`，默认 30d，禁止共享缓存；未登录 401、普通用户/编辑 403、错误范围 400、数据库失败 503，不伪装成零数据。
- 复用 `content_metrics_hourly`（PV）与 `view_history`（登录用户访问）；不增加匿名标识或数据库迁移，schema 仍为 27。一次只读 REPEATABLE READ 事务保证同份报表一致。
- 时间口径：上海时区自然日，7/30 天含今日；累计含现存全部历史，累计趋势仅展示最近 30 天；过滤未来记录、补齐零访问日期。既有前台热门作品采用滚动窗口，与后台自然日口径不同。
- 指标：今日详情 PV、范围 PV、普通登录用户访问次数、访问过的去重注册用户数。后两项排除 `is_test`、管理角色和关闭账号；已软清除但尚留存的历史仍参与计算。这是现存历史记录统计，若以后启用归档删除会减少，并非独立永久用户计数器。
- 全站 UV 为 `null`/“暂未统计”。仅有登录账号去重无法代表匿名独立访客，不新增未经确认的追踪机制。
- 热榜：当前公开作品/人物/厂牌按范围 PV 降序，前 20 条，显式排名与访问次数；同次数按类型/ID 稳定排序。下架或已删除实体的历史访问可保留在总量，但不会上榜，故总量不要求等于榜单加总。
- 用户表：前 50 名普通注册用户的邮箱与次数，仅后台管理权限返回，不输出个人看过哪些资料。列表、翻页、搜索和内部采集预览不作为详情 PV。
- 本地测试用精确命名的独立 PostgreSQL 克隆 `self_deepsearch_traffic_test_20260919`，拒绝向其他数据库执行测试写入；使用后删除。主联调环境保持零模拟实体。
- 已修复真实数据库测试发现的 SQL 日期别名语法错误。非零数据验证：7d PV=32、30d PV=52、累计 PV=63，今日 29；普通用户次数 2/3/3、去重 1；管理/测试/关闭账号与未来事件不计入，零日期补齐，下架对象不上榜。
