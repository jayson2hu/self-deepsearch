# DEV-01 样本与合同基线

版本：RD v1 / DEV-01；基准日期：2026-09-16；评审源码：`d79b304`；评审时 Schema：v21。此文件冻结后续开发测试输入，不表示计划中的接口已经实现。

## 1. 可复用样本

- [核心目录夹具](../../tests/redesign/fixtures/catalog-baseline.mjs)：36 条纯合成记录，其中作品 24、人物 7、厂牌 5；覆盖长标题、同名、别名、同番号多版本、无图、未知发行日期、旧接口缺字段，以及 published/draft/hidden/takedown。
- 同一夹具包含 24 条带标准答案的查询，覆盖作品、人物、厂牌；明确列出应返回和必须排除的实体，后续 DEV-08/09 记录实际排序差异时不得改写预期掩盖回归。
- 边界生成器提供人物关联 101 条、厂牌关联 201 条和 sitemap 50,001 条数据。它们按需生成，不提交庞大的静态副本。
- 所有域名使用 `.example.test`，没有真实邮箱、账号、浏览历史、来源证据或未公开资料。

## 2. 合同冻结

[机器可读合同快照](../../tests/redesign/contracts/rd-v1-contract-baseline.json)区分两类事实：

- 当前合同：作品搜索和三类详情端点存在；搜索只返回作品；人物/厂牌详情仍内嵌有限作品；详情没有 `public_updated_at`，作品没有 `studio` 对象。
- 计划合同：DEV-03 追加更新时间和厂牌对象；DEV-09 新增人物/厂牌搜索；DEV-10 新增两类关联分页。旧作品搜索、`studio_name` 和内嵌 works 在迁移期保持兼容。

后续实现若改变计划合同，先更新决策/技术设计，再更新快照及测试。不能通过直接修改生成类型或删除失败断言来制造通过。

## 3. 自动检查

执行：

```bash
node scripts/tests/redesign_baseline.test.mjs
npm run check:markdown-links
```

第一条验证样本数量、状态与边界、标准查询、当前 OpenAPI 和 DEV/AC/决策编号映射；第二条验证全仓 Markdown 本地链接。真实 PostgreSQL、浏览器、目标对象存储与公网环境不属于 DEV-01 的通过证据，进入对应 DEV 后执行。

## 4. 使用约束

- 核心样本用于单元、合约、预览和浏览器测试；需要真实 SQL 时由隔离数据库种子转换，不直接写现有业务库。
- 大容量生成器证明输入边界，不等于已经通过分页、地图体积或并发变更验收。
- 新 DEV 可扩充样本，但应保留既有 ID 和语义；必须变更标准答案时在进度日志说明产品规则或合同变化。
- 发布、历史保留、真实广告和正式索引仍受各自决策与门禁约束，合成夹具不得启用外部能力。
