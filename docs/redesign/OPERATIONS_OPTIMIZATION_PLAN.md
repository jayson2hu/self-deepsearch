## 1. 如何使用与交付边界

执行顺序：确认范围 → 认领工作包 → 先写合同和失败测试 → 开发 → 分层测试 → 提交实现代码 → 对固定提交复测 → 记录证据与汇报 → 产品验收 → 单独申请发布。

- 本轮第一阶段交付：用户统计与分页、广告页面治理与管理、SEO 站内诊断和优化任务闭环。
- 第二阶段交付：搜索效果报表与目标环境验证；允许先实现无数据状态及使用明确标识的合成数据测试，真实效果验收必须等待真实来源。
- 不做：广告竞价/结算/付费开户、任意第三方脚本、跨站追踪、自动购买外链、全站重写、用户历史清理、未经授权的生产数据读取、自动给管理员提权。
- 现有 RD 的 DEV-01～15 与本轮 OPT-00～08 分开核算，旧版通过不替代新增功能验收。既有遗留阻塞参见[总进度台账](./PROGRESS.md)和[验收执行标准](./ACCEPTANCE_EXECUTION_STANDARD.md)。

## 2. 产品设计与固定口径

### 2.1 广告页面规则

| 页面 | 首期位置 | 数量与禁止项 |
| --- | --- | --- |
| 首页 | 最新内容区后一个横幅；宽屏可另加右侧栏 | 不占搜索入口，不连续堆叠 banner 与 infeed |
| 作品/人物/厂牌详情 | 核心资料后、关联内容前；宽屏可另加右侧栏 | 不把广告插在标题与资料之间 |
| 最新/热门/完整目录 | 当前页至少 12 个自然内容时，在第 8 个之后 | 正文一个；不足 12 个不展示 |
| 搜索结果 | 首期无广告 | 不实现后续候选的搜索信息流广告 |
| 登录/注册/找回密码/邀请/个人中心/隐私/权利申诉/后台 | 整页无广告 | 包括共享页脚，不依赖调用方自行记得关闭 |
| 空态/错误页/404/503 | 无广告 | 不保留大块空白，不展示预览假素材 |

视口宽度小于 1200px：最多一个可见广告且不展示侧栏；大于等于 1200px：最多两个，仅允许单侧栏。320/390/768/1440px 均须测试，另补 1199/1200px 边界。匿名与登录用户规则相同；没有有效素材就没有广告占位。全局页脚不再默认投放。

广告必须标注“广告”及广告主，链接保留 sponsored/noopener/noreferrer；无自动弹窗、遮屏或底部悬浮。素材有正确尺寸与替代文本，支持键盘访问。首页与详情关键内容不得依赖广告服务成功才显示。

### 2.2 用户后台与统计口径

后台 `/users`：统计卡片 → 邮箱/ID 查询与角色/状态/时间筛选 → 分页列表 → 用户详情和审计。列表显示用户 ID、邮箱、角色、状态、验证情况、创建时间、最近登录；不默认展示个人浏览记录，不做密码读取或代登录。

| 指标 | v1 定义 |
| --- | --- |
| 当前账号总数 | 当前账号表所有记录，包含管理、测试与关闭账号；页面显著标注环境 |
| 当前普通账号 | role=user，包含非 active 状态；不等同累计公开注册 |
| 启用普通账号 | role=user 且 account_status=active |
| 已验证普通账号 | role=user 且验证时间非空，关闭账号是否包含必须在卡片说明中明确；v1 包含 |
| 管理账号/关闭账号 | 分别按角色集合、closed 状态计数；两者可能交叉，不能相加当总数 |
| 累计公开注册 | origin=public_signup、已完成首次邮箱验证、is_test=false 的注册事实数；后续提权/关闭不减少 |
| 今日/近 7 日公开注册 | 根据首次完成注册时间，Asia/Shanghai 今日或含今日的 7 个自然日；不是过去 168 小时 |
| 历史来源未知 | 单独显示数量及统计覆盖起点；不能猜测归入公开注册或展示虚假的全历史累计 |

新增注册来源 `public_signup/invitation/bootstrap/fixture/unknown` 和明确测试标记，来源由可信服务端流程写入，不能接受注册请求自行声明。首次完成验证的注册事实须事务内幂等记录，重复验证不重复计数。旧记录默认 unknown；仅有可靠证据才回填，附审计。历史缺失时卡片命名为“自 YYYY-MM-DD 起已记录公开注册”，不假称全站历史总数。

本轮不新增个人活动追踪，故不提供 DAU。当前测试库历史快照为 3 条账号记录、0 个普通账号，详见审查文档；开发和验收必须重新查询，不能把这个快照硬编码到 UI 或测试。

### 2.3 SEO 与优化任务

后台新增 `/seo` 总览与页面清单、`/seo/issues` 问题列表。展示站内可索引数量、排除原因、待分类、sitemap 候选数量、扫描时间和失败情况；不把“可索引”写成“已收录”。

详情需展示实际输出的标题、描述、canonical、robots、内容/媒体策略、更新时间、规则证据和整改入口。内容修改回到既有修订发布流程，不直接更新公开数据库。首期先沿用现有标题/描述生成模板；自由模板管理和单页 SEO 覆盖字段不进入本轮，以免另造编辑系统。

问题字段：规则编码、URL/实体、优先级、首次/最近发现时间、证据、责任人、截止日、状态、处理说明、复测记录。状态为待处理→处理中→待复测→已关闭；复测失败回到处理中；同一 URL+规则仅一个未关闭问题，再次出现可重开并保留历史。不能仅点按钮关闭仍然存在的错误。

P0：服务错误、流式渲染失败、私有内容暴露、错误生产 origin；P1：意外 noindex、地图资格不一致、未知分类、重复标题、异常死链；P2：内容关联、图像与性能改进。预期 404/下架 410 不自动认定为缺陷。

Search Console 第一版采用授权负责人提供的官方导出数据导入，不默认接入 OAuth/API；展示站点、来源、时间区间、导出时间与数据完整性。搜索表现和索引报告分开记录，展示未连接、过期、导入失败、无数据状态。合成数据显著标注“演示”，不并入真实报表。自动接入另立变更。

SEO 官方依据延续[已核验的正式方案](../PRODUCT_SEO_PLAN.md)及[本次审查来源](./OPERATIONS_REVIEW_2026-09-17.md)，不承诺排名和收录期限。

## 3. 架构、接口与数据合同

### 3.1 复用边界与拟新增接口

前台负责展示，ops-web 负责管理交互，platform-api 强制执行权限、校验和审计，PostgreSQL 保存配置与任务；复用现有 Worker/任务机制执行扫描与缓存通知，不另建微服务。实现前同步 [OpenAPI](../../packages/api-contracts/openapi.yaml) 并生成类型。

下表仅为**拟新增或扩展合同，不表示路由已经存在**。新增读取接口统一分页元数据，错误沿用仓库既有结构。

| 接口/合同 | 行为 |
| --- | --- |
| 扩展 GET `/admin/v1/users` | q、role、status、created_from/to、cursor、limit；保留 items，增加分页及筛选计数 |
| GET `/admin/v1/users/summary` | 环境、observed_at、口径版本、当前账号分类与有覆盖说明的注册量；路由避免被动态 ID 捕获 |
| GET `/admin/v1/users/{id}` | 最小必要账号资料；既有角色/状态端点继续复用 |
| GET/POST `/admin/v1/ads`，GET/PATCH `/admin/v1/ads/{id}` | 列表、创建、查看、编辑草稿；乐观锁防覆盖 |
| POST `/admin/v1/ads/{id}/publish`、`/pause` | 发布指定草稿版本或紧急暂停，近期验证、审计、幂等 |
| GET `/public/v1/ads` | 仅返回允许公开的有效素材及稳定槽位，不泄露内部原因/操作者；参数限制为页面类型与合法槽位 |
| GET `/admin/v1/seo/summary`、`/pages`、`/issues` | 从既有资格规则与扫描事实读取，返回最近扫描时间和覆盖范围 |
| POST `/admin/v1/seo/scans`，PATCH `/admin/v1/seo/issues/{id}` | 有界扫描任务；仅允许合法分派与状态转换，关闭要求复测证据 |
| POST `/admin/v1/seo/reports/import` | owner 导入官方导出文件，验证站点、类型、时间区间和字段；不执行文件内容 |

分页默认 25、最大 100；排序为 created_at DESC、ID ASC，游标绑定筛选条件、排序元组和首请求时间上界；非法/跨筛选游标返回 400。固定数据集遍历不重不漏；并发新增不插入本次遍历，修改角色/状态可能改变筛选集合，UI 提示刷新，不承诺跨请求数据库快照。单次返回的分类计数使用同一读取快照；注册时间筛选与创建时间筛选不可混用。

### 3.2 数据模型与兼容发布

- 用户：增加服务端来源/测试标记，以及首次完成注册事实；唯一键防重复，角色变化不修改历史来源。与用户关闭逻辑兼容，不改变既有删除/保留政策；如涉及将来永久删除，另行批准聚合及去标识策略。
- 广告：配置主记录、不可变版本/草稿、发布版本引用、暂停标记、版本号和审计。修改草稿不得使线上正在投放的版本变化；发布切换引用，暂停优先于一切版本。计划中/投放中/过期由已发布版本和时间计算，避免定时任务延迟导致错误投放。
- 广告版本字段：稳定槽位、页面范围、设备范围、广告主、素材地址/尺寸/替代文本、跳转地址、优先级、starts_at/ends_at、校验结果。时间以 UTC 存储，界面显示 Asia/Shanghai。时间区间 `[starts_at, ends_at)`；同槽按优先级降序、发布时刻降序、ID 升序选择一个。
- SEO：扫描任务、逐页规则结果、问题单/历史、外部报表元数据与指标。复用已有内容分类和质量字段，不建立相反的 indexable 开关。报告文件限定 5 MiB、10,000 行，按类型校验；源文件非公开，拒绝公式执行及路径穿越。
- 迁移序号取开工时最新未占用序号，不假定仍停在 v22。先扩展兼容 schema→API/Worker→后台→前台；旧客户端可读取 items。新入口默认关闭，验证后放开，不自动开放真实广告或生产索引。
- 迁移测试覆盖空库和旧版合成库、重复部署、备份恢复。破坏性 Down 仅在一次性库测试；有真实新增数据时禁止直接 Down，优先回退应用并保留兼容 schema。

### 3.3 广告配置与缓存时效

`DISPLAY_ADS_ENABLED=false` 保留为最高级熔断。增加明确的配置来源 env/backend：ADS-01 用稳定槽位兼容已有 env 配置，ADS-02 才引入后台来源；两者不得叠加。选择 backend 后若读取失败返回无广告，不偷偷回退至过期 env 广告。

投放配置最长缓存 30 秒，且 TTL 不超过下一生效/到期边界；禁用 stale-while-revalidate/stale-if-error 保留旧广告。发布或暂停提交成功后通过既有通知机制使全部相关缓存失效，失败可重试；停止服务的实例重启不得加载已过期本地配置。

验收时限：暂停成功起 **60 秒内，所有新请求和路由导航不再出现该广告**；已打开页面的到期素材到点移除，暂停配置每 30 秒重检，前台活动页在 60 秒内停止展示，标签恢复可见时先重检。离线且无法确认有效配置时隐藏广告。该公共配置重检不采集用户标识。

如广告被渲染进页面 HTML，还必须同步约束页面/CDN 缓存；做不到时将广告数据与长缓存正文分离，并通过真实浏览器验证无明显布局跳动。不能只测 API 缓存就宣称整个页面符合停投时限。

### 3.4 权限、安全与巡检约束

| 操作 | owner | admin | editor/普通用户/匿名 |
| --- | --- | --- | --- |
| 用户读取与普通账号状态 | 允许，保留自保护 | 允许，禁止操作更高权限账号 | 禁止 |
| 角色调整 | 既有权限范围内允许，禁止自提权/破坏 owner 保护 | 禁止 | 禁止 |
| 广告读取/草稿 | 允许 | 允许 | 禁止 |
| 广告发布/暂停 | 允许，近期验证 | 禁止 | 禁止 |
| SEO 中心读取/问题处理 | 允许 | 允许 | 首期禁止；editor 保留原内容修订权限 |
| 外部报表导入 | 允许 | 禁止 | 禁止 |

认证、CSRF/Origin、近期验证、审计按既有安全机制扩展；敏感新路由必须纳入服务端匹配规则。用户和后台数据不得进入公共缓存，API 拒绝越权而不只隐藏按钮。审计不记录密码、令牌、完整导出文件或个人浏览历史。

SEO 扫描默认每日一次，允许手动触发；每批最多 1,000 个规范站内 URL，稳定游标继续下一批；每站最多一个活动任务、并发最多 2、单请求超时 10 秒、瞬时失败最多重试 2 次。批次覆盖量/跳过/失败显式显示，不把抽样称为全站完成。

扫描目标从内部实体清单产生，不接受任意 URL；仅允许部署配置固定的本环境 origin，禁止跟随至外站、云元数据地址或任意私网目标，限制响应体 2 MiB。测试环境只允许显式配置的固定测试服务，不开放通用私网抓取。扫描失败不得开放索引或自动关闭历史问题。

## 5. 测试策略与执行要求

### 5.1 分层测试

沿用既有六层门禁：A 文档/静态，B 单元/合同，C 构建/制品，D 真实隔离栈，E 真实浏览器，F 目标与外部。新增功能必须测试成功、失败、空态、边界、越权和回退；字符串合同检查不能替代业务执行。

只使用明确命名的 OPT 专用测试库、邮件箱和合成素材；不得把当前用户正在审查的环境当成可清空的测试库。创建资源前记录名称和用途；清理仅限本次明确创建的目标，不执行模糊匹配删除或清空整个 Docker 环境。

## 7. 结果、证据和验收打包

结果采用 PASS / FAIL / PARTIAL / BLOCKED / NOT_APPLICABLE；未执行用例另记 NOT_RUN。PASS 必须所有适用断言与证据齐备；部分通过和环境阻塞不计通过。NOT_APPLICABLE 必须由负责人确认范围理由，不能用于绕过浏览器或已发生的失败。

每包创建证据目录，路径模板为 `docs/evidence/operations-opt-YYYY-MM-DD/OPT-XX/`（开发时创建，本次不生成假报告）。至少包括：

```text
README.md          结论、范围、复现命令、限制、下一步
manifest.json      代码 SHA、环境、制品 digest、工具版本、开始/结束时间
results.json       OA 编号、结果、预期/实际、命令退出码、证据路径
commands.log       脱敏命令及关键输出
screenshots/       页面/宽度/状态命名的截图
traces/            真实浏览器 trace 或报告
blockers.md        原因、尝试、影响、负责人、解锁条件、复测命令
```

OPT-08 聚合所有包，补迁移/备份恢复记录、发布配置差异、回退步骤、文件 SHA-256 清单及签收表；需要分发时生成同目录结构的压缩包并提供校验值。大体积 trace/镜像可放受控制品存储，仓库记录可访问位置、保留期限与哈希；凭据和用户个人数据不得入库。

缺陷修复追加新记录，不覆盖首次失败。复测必须针对新提交，说明哪些旧证据仍有效；行为相关代码变化后不能直接沿用旧 PASS。文档校验成功不等于功能验收通过。

签收分四项：开发自测（执行人）→测试复核（执行人）→产品验收（负责人）→生产发布（有权限负责人）。没有独立测试人时注明“开发自测，待独立复核”，不得虚构人员。没有最终 HTTPS、授权报表/外部条件或既有发布门禁未满足时，可以交付本地已通过部分，但整体不得写“可上线”。
