## 3. 配置和迁移交接

1. 先备份并核对恢复手册，再将 Schema v21 迁移到 v22；使用受限运行账号复核视图与权限。
2. 先部署 API/Worker，再部署 display-web/ops-web；对照 OpenAPI 和生成类型。
3. `SITE_URL` 必须是最终 HTTPS origin；测试、IP、回环和临时域名不允许放行索引。
4. 首次部署保持 `SEO_INDEXING_ENABLED=false` 与 `SEO_CONTENT_POLICY_READY=false`。完成生产存量统计、抽样、回填和 [DEV-14 放行单](./DEV14_SEO_RELEASE_GATE.md) B/C 阶段后，才能同时设为 `true`。
5. 广告继续默认关闭；只有 Q-05 的真实素材、域名和负责人确认后才能启用。
6. Q-01 未签署时不新增历史开关、保留期或清理任务。

## 4. 目标环境发布顺序

1. 记录代码 SHA、容器 digest、数据库备份 ID、配置变更单和当值人。

## 5. 回退顺序

1. 索引、分类或图片预览异常时，先关闭 `SEO_INDEXING_ENABLED`，确认 robots 和 HTML/X-Robots-Tag 恢复 fail-closed。
2. 回退前端/API/Worker 容器到已记录 digest；复核 200/301/400/404/503、登录、搜索和后台权限。
3. 默认保留 Schema v22：新列对显式列查询的旧应用兼容，可避免丢失已录入的审核结论。
4. 只在独立恢复演练已通过、已停止新策略写入并有完整备份时考虑 v22 Down；Down 会删除分类/预览结论，不是常规应用回退步骤。
5. 搜索引擎已抓取内容不会因代码回退立即消失；由已验证所有者记录移除/重抓操作。
