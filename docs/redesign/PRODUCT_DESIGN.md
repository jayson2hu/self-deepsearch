# 产品与交互设计规格

版本 RD v1 / 2026-09-16。依据：[决策记录](./DECISIONS.md)。本稿为开发规格，不是已实现页面；高保真截图与浏览器证据将在对应 DEV 任务中补齐。

## 1. 目标与非目标

首要路径：输入番号/名称 → 判断结果 → 查看资料 → 收藏或关注 → 继续浏览。第二路径：人物/厂牌 → 关联作品 → 详情。用户不必理解录入、核验或审核流程。

沿用既有视觉基础与默认图，调整布局和组件职责，不在本轮更换技术栈、品牌、媒体存储或账号体系。不建设视频/下载、社交、公开用户收藏、未读通知系统、自动采集或广告结算。

## 2. 页面与导航

| 页面 | 路径 | 主任务与主要操作 |
| --- | --- | --- |
| 首页 | `/` | 搜索；进入一个主要目录；有内容时提供简洁推荐/关注入口 |
| 搜索 | `/search?q=...&type=work` | 保留搜索词，识别实体，进入详情；后续支持 performer/studio |
| 作品 | `/works/{slug}` | 确认番号/标题、复制、收藏、人物与厂牌关联 |
| 人物/厂牌 | 既有 `/performers/{slug}`、`/studios/{slug}` | 确认名称、查看公开更新时间、继续看关联作品 |
| 目录 | 既有 latest/recent/performers/studios | 明确排序，真实下一页；不因“不感兴趣”挡住主动查询 |
| 我的 | 既有 account 路由 | 收藏、关注、历史、偏好管理、反馈、设置 |
| 说明 | 新增 `/privacy`、`/about` | 描述实际行为、资料边界和联系方法；匿名可访问 |

桌面主导航保留“查询 / 浏览 / 人物 / 我的”层级；浏览中可到厂牌、最新、最近收录。手机页头始终有搜索入口和账号入口，不引入新的底部导航作为依赖。所有入口有文字或可访问名称。

### 首页与详情布局顺序

```text
手机首页                        手机作品详情
页头：品牌 / 搜索 / 我的         页头：搜索 / 我的
主搜索框 + 简短范围说明          返回结果（可用时）/ 面包屑
一个主目录及继续浏览入口         番号、完整标题、复制 / 收藏
有数据才出现的推荐/关注内容       发行日期、人物、厂牌、资料更新时间
有效广告（可选，正文之后）       主图 / 默认图、公开资料
说明与联系                      关联作品、有效广告（可选）、纠错/说明
```

手机详情首屏优先显示身份和主要操作；大图不先占满一屏。桌面可分栏，但 DOM 阅读顺序与手机一致。首轮不改变当前最多 1 张主图 + 3 张精选图的媒体限制。

## 3. 首页与资料详情

### 首页

- 搜索提示按能力分期：阶段 A 写“番号、标题；人物或厂牌名称可查关联作品”；阶段 B 才承诺三类实体结果。
- 默认突出最新发行；没有可信发行日期的资料进入最近收录。全空目录只显示一组说明和下一步；不摆多个空榜单。
- 无有效统计不显示热门；同一资料不在首屏重复堆叠。关注内容只在对应用户确有数据时出现，不写入共享 HTML。
- 保留简短“18+ / 公开资料索引 / 不提供播放下载”边界和说明链接，不出现“审核队列”“核验中”“混排规则”等内部术语。

### 详情

- 作品显示标题与番号；人物/厂牌显示公开名称。原有正常资料字段不因 D-07 被整页删除。
- 新增文案 `资料更新：YYYY-MM-DD`；使用 `<time datetime="RFC3339">`，日期展示统一为 Asia/Shanghai。说明其为本站公开文字资料的发布更新时间，不是发行日期或核验时间。
- 字段名 `public_updated_at`；确实缺失时不显示日期，不写“刚刚更新”，也不拿浏览器当前时间补齐。详见技术方案。
- 不新增公开来源类型、来源标题列表、核验状态、操作人、审核承诺或审核流程面板。来源/核验数据仅保留内部用途。
- 人物和有效厂牌名称均为链接；无厂牌时不造空链接。保留可读发行日期未知状态、可选字段缺失状态和不同版本差异。
- 复制番号后提示成功；权限或浏览器能力不足时提示手动复制，不宣称已复制。
- 纠错是简洁入口，不迫使访客阅读处理工作流；用户主动提交后的个人反馈状态仍可见。

## 4. 搜索与关联浏览

阶段 A：仍调用作品搜索。编号精确匹配优先；人物艺名/别名可能命中关联作品，要解释当前范围。允许清空与改词；无结果不显示服务错误，服务错误也不显示为无结果。

阶段 B：采用“作品 / 人物 / 厂牌”三个类型标签，默认作品；不增加无法稳定比较相关性的“全部”混排。每个标签单独查询、独立游标；切换类型保留 q 并清除 cursor；返回详情前的搜索 URL 可恢复查询条件。

| 状态 | UI 行为 | 不允许 |
| --- | --- | --- |
| 空词 | 示例与输入焦点；不请求无边界全量搜索 | 伪造热门词或虚构历史 |
| 不合法 | 保留输入、指出限制 | 静默改成另一查询 |
| 请求中 | 保留搜索框/条件，结果区有加载提示 | 让旧结果冒充新词结果 |
| 有结果 | 显示真实实体类型、番号/名称、足以区分的已有字段 | 伪造匹配原因、评分、总数量 |
| 无结果 | 清楚说明未找到，可改词/换类型/浏览目录 | 把网络失败记作零结果 |
| 故障 | 重试且保留条件 | 返回空数组并显示“未收录” |
| 非法或过期游标 | 提示从第一页重试，保留 q/type | 无提示地重复第一页 |

同名、别名、同番号不同版本不得自动合并。关联作品默认按发行日期降序、未知日期靠后，再按稳定字段排序；下一页使用真实 href。暂停使用前端一次拿完 100/200 条再“假分页”的方式。

## 5. 登录后的任务续接

```text
游客点击收藏/关注
  → 登录页（保存站内目标与动作意图）
  → 可切换注册/密码重置，目标不丢
  → 登录成功，回到原资料
  → 显示“继续收藏/关注”确认
  → 调用既有接口，显示真实结果并清除意图
```

这是本版技术设计的保守动作规则：登录成功不靠页面 GET 自动写数据；用户回到目标后确认，防止重放、共享链接或切换账号造成隐式操作。已收藏/已关注直接显示当前状态，不重复“toggle”。

取消或离开登录不写关系；失败保留目标；目标已下架显示不可用并提供搜索入口；动作过期只返回页面、不执行。隐藏、纠错提交、关闭账号等动作不属于自动续接白名单。默认的普通登录仍回首页。

## 6. “不感兴趣”场景矩阵

| 场景 | 应用个人不感兴趣过滤 | 说明 |
| --- | --- | --- |
| 首页个性化发现、编辑/热门推荐区 | 是 | 属于被动推荐 |
| 作品详情的“你可能感兴趣/相关作品” | 是 | 仍可在搜索和目录主动找回 |
| 搜索三类结果 | 否 | 明确查找不被偏好屏蔽 |
| 最新/最近收录完整目录 | 否 | 主动浏览目录，不是推荐流 |
| 人物/厂牌完整关联作品 | 否 | 用户指定对象后的完整关系 |
| 收藏、历史、关注人物的明确作品列表 | 否 | 用户已经主动选择；管理员下架另行过滤 |
| 直接详情与偏好管理 | 否 | 能恢复推荐偏好；不能恢复权利下架内容 |

统一文案为“不再推荐”；成功提示“已减少这部作品的推荐，仍可搜索找到”，提供撤销。账号菜单可写“推荐偏好”，兼容原 `/account/hidden` 路径，无需 URL 迁移。

偏好加载失败时可降级为完整公开推荐并提示重试；不得假装偏好已生效。私有偏好状态只在用户上下文处理，不进入公开页面缓存。管理员 hidden/takedown 在所有公开入口过滤，永远不能用个人“恢复”按钮恢复。

## 7. 广告状态与权限

| 状态 | 普通访客/登录用户 | 设计测试 |
| --- | --- | --- |
| 无广告、禁用、无填充 | 不渲染广告容器及空白高度 | 受控预览可用测试占位 |
| 有合法有效广告且成功加载 | 均显示，明确标“广告”，与资料卡分隔 | 验证真实布局，不伪造上线 |
| 过期、加载失败、来源拒绝 | 不展示广告，不影响正文和操作 | 能复现错误状态 |
| 只有占位组件、没有素材 | 等同无广告，不拿占位冒充广告 | 仅在受保护环境显示“测试素材” |

DEV-05 只实现上述状态和已有位置复用，默认关闭素材输出；没有已确认供应方时不引入第三方 SDK、结算或追踪。生产不能通过公开 `?previewAds=1` 开启测试占位。先确定可用素材与尺寸再渲染，避免晚插入把收藏按钮挤走。

## 8. 历史、说明和账号入口

阶段 A 的说明必须反映当前实现：注册登录能力、个人历史记录、可见历史软清除、关闭账号不等于物理删除、归档/审计边界、反馈和联系入口。说明页匿名可达，注册前、历史页与设置页可找到。文案事实需逐条与当前代码核对，不能宣称已经有限保留。

阶段 B 的历史开关/期限方案待 Q-01。设置原型可以表达“主动开启历史同步”的候选，但不发布不可兑现的“已停止记录/已删除全部”按钮。普通收藏/关注不以开启历史为条件。

“我的”继续使用现有页面；关注页提供已有关注作品入口，文案区分新发行和本站新收录。反馈的用户状态解释为“已收到/处理中/已处理”等需映射真实现有枚举；无公开回复字段时不展示内部处理理由。新消息未读、多设备通知和邮件推送均延后。

## 9. 视觉与交互交付标准

使用现有组件与 CSS，交付首页、搜索、三类详情、登录/注册、说明及账号入口的手机/桌面实现证据。至少检查 320/390/768/1440 宽度，手机主样本 390×844；普通正文无整页横向滚动，长标题和键盘焦点不被固定栏遮挡。

按钮/表单具备可访问名称、可见焦点、加载和失败说明；不用只靠颜色表示状态。缺图、日期未知、长名称、故障、下架、无广告/有广告必须有样本。验收是可执行 AC 用例，而不是“页面看起来差不多”。

## 10. SEO 纳入设计但不越权开放

详情 title/H1/description 使用真实公开字段；来源证据不作为前台必须展示项；不能为了 SEO 重加 D-07 已移除的审核面板。内链、面包屑、canonical 和分页按技术方案实现。更新时间不等于搜索收录保证。

D-08/D-09 已按用户后续授权采用[正式 SEO 方案](../PRODUCT_SEO_PLAN.md)：首期中文，Google 官方机制为技术基准，不预设已验证地区或新增外语站。合格公开详情、真实目录及合法不同内容分页允许索引；搜索、账号、测试/演示、低质量和未发布内容不入索引。关于页在真实信息完整时可索引，工具说明页不作为获客页面。

图片预览仅用获准外部展示、分类明确且非露骨的公开派生图；受限图片使用品牌 OG 图并同步资源与页面限制。包含露骨内容的页如实标记 adult，不通过隐藏性质或取消访问限制争取流量。资格、preview 指令和字段降级以正式 SEO 方案为准。

这不是立即开放索引：测试站继续受保护；真实域名、部署放行和工具权限满足后由发布流程提交。用例不再等待 D-08/D-09 的产品选项；仍不新建批量换词专题、无真实翻译的多语言站或虚假排名目标。
