# DEV-12 历史生命周期决策门禁

状态：待产品负责人确认；本文件不是已生效政策，不改变代码、数据库、Worker 或用户数据。

## 当前可证明事实

- 登录用户访问作品、人物、厂牌详情时，服务端默认追加个人浏览历史；匿名访问不写个人历史。
- 当前没有 `history_sync_enabled` 或等价服务端开关。
- “清除可见历史”是软清除：记录不再通过账号页展示，但数据库原行没有物理删除。
- 历史归档 Worker 默认关闭；即使启用，当前也只归档已软清除记录，不删除数据库原行。
- 当前没有覆盖在线表、归档对象和备份恢复的统一保留期限。
- 关闭账号会关闭登录并撤销会话，不等于物理删除历史、反馈、审计或安全记录。

事实证据见[隐私事实清单](./PRIVACY_FACTS.md)。

## 开发前必须确认的四项决定

| 决定 | 必须给出的值 | 候选方向与影响 |
| --- | --- | --- |
| 新用户默认值 | 开启 / 关闭 | 推荐“关闭、用户主动开启”；若开启，必须在注册前准确披露 |
| 旧用户迁移 | 保持开启 / 停止未来写入待用户选择 / 其他明确规则 | 影响上线瞬间的写入行为；不能把沉默当作同意，也不能在无迁移记录时静默改写偏好 |
| 生命周期期限 | 未清除在线记录、已清除在线记录、归档对象、备份各自的明确期限 | 需要给出具体数字和起算点；“有限保留”不能只覆盖页面可见记录 |
| 删除与恢复边界 | 到期删除哪些对象；备份恢复后如何防止复活 | 必须说明不可逆范围、恢复抑制标记和旧二进制回退限制 |

## 建议产品原则

- 新用户采用主动开启，不把浏览历史作为收藏、关注或账号使用的前提。
- “停止未来记录”“清除当前可见记录”“到期物理删除”“删除归档”“备份到期”是五个独立动作，UI 和 API 不合并承诺。
- 设置更新返回成功后发起的新详情请求不得再写个人历史；必须在服务端强制，不能只关闭前端上报。
- 匿名小时级聚合指标与账号逐条历史分离；关闭个人历史不暗改公开访问指标口径。
- 旧用户迁移、并发设置/写入、归档到期、备份恢复和旧版本回退必须同批验收。

## 当前禁止动作

- 不新增只改变页面外观、但服务端仍继续写入的假开关。
- 不填写未经批准的 30/90/180 天等期限。
- 不运行历史物理清理、归档删除或备份删除。
- 不用真实浏览历史、邮箱或未公开审核资料做测试样本。
- 不把回滚到忽略偏好的旧 API 当作安全回退。
