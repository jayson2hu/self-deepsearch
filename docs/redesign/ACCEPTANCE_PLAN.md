# 验收计划与用例

版本 RD v1 / 2026-09-16。状态：用例规格已编制，产品功能尚未执行本轮验收。30 个 AC 是用例组，不把组数当断言数或完成百分比。实际结果见[进度台账](./PROGRESS.md)。

## 1. 分层与门禁

| 层 | 证明什么 | 不能替代什么 |
| --- | --- | --- |
| 文档检查 | 审核有追踪、路径有效、任务/用例对应 | 功能实现、产品认可或法律审查 |
| 静态/单元/合约 | 类型一致、规则和负例可验证 | 真实 SQL 与运行响应 |
| 合成预览浏览器 | UI、空态、尺寸、交互 | 真实 API、权限、发布缓存、线上性能 |
| 真实隔离 PG/API/Worker/邮件/Next | 登录、发布、下架、缓存与数据一致性 | 真实对象存储、公网域名、边缘与两地部署 |
| 目标环境 | 最终制品、域名、边缘、媒体、外部能力 | 没有足量真实用户数据时的长期增长结论 |

任一适用用例失败不能记为通过；skip 必须解释且不能计入通过数。阻塞记录阻塞原因/解锁条件；不适用必须由交付范围决定，不能为凑通过率排除失败项。

## 2. 数据与设备

使用合成或获准资料，禁止把真实浏览历史、邮箱和未公开审核证据写到测试报告。样本覆盖作品/人物/厂牌、长标题、中文/日文、艺名别名、同名、同番号多版本、缺图、未知日期、多个关联、草稿/已发布/隐藏/下架。

UI 宽度 320/390/768/1440，手机基准 390×844；桌面至少一次键盘遍历。搜索静态数据跨至少两页；关联作品分别大于 100/200；sitemap 单类 50,001+ 条、体积边界。数据变更/并发写入独立测，不与静态无重漏混淆。

## 4. 建议执行命令与前置

以下均为开发后的执行入口，不表示本次已运行。不得对现有业务数据库直接执行隔离测试脚本。命令以仓库当前 package.json / CI 为准，新增测试加入既有入口；如果命令失败，保留失败和根因，不改报告写成通过。

文档和静态：

```bash
npm run check:markdown-links
npm run check:api-types
npm run typecheck
npm run lint
npm run test:frontend:smoke
npm run test:preflight
go vet ./services/platform-api/... ./services/platform-worker/...
go test ./services/platform-api/... ./services/platform-worker/...
```

前端构建与合成浏览器（已安装对应浏览器、使用隔离预览配置）：

```bash
npm run build
npm run smoke:frontend:release-a
npm run test:e2e:release-a
npm run test:cache:release-a
npm run probe:performance:release-a
```

真实栈用 `npm run test:e2e:real-stack` 对应运行器，先阅读[既有运行手册](../RELEASE_A_RUNBOOK.md)和[CI 前置](../../.github/workflows/ci.yml)，准备隔离 PG/Mailpit、受限角色及 Worker，明确创建与清理的目标。仓储、迁移、race 与 Python/归档相关测试按实际改动补跑。没有数据库配置而跳过的测试不得算真实 SQL 通过。

性能目标沿用 SEO 方案 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 的真实用户第 75 百分位观察口径；开发阶段实验室报告与该目标分别记录。真实流量不足填“数据不足”，不能因此伪造达标，也不能用合成 API 时间替代线上字段。

每批在 `docs/evidence` 新建有日期与批次号的目录，不覆盖旧证据。该目录尚未在本次文档任务创建，不预先制造通过报告。

不适用及原因、未覆盖风险：

开发者记录测试，产品负责人确认功能范围；真实外部依赖由具备权限的负责人执行。没有另一位验收人时记录“开发者自测，待产品复核”，不能虚构独立签收。
