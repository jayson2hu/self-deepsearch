## 1. 使用规则

P0 表示核心任务或开放真实用户前的产品基础；P1 表示持续使用与运营效率；P2 表示有前置证据后再评估。优先级不替代安全等级或 [Release A 放行标准](./RELEASE_A_READINESS.md)。

工作量仅表示相对范围：S 为局部页面/文案，M 为跨页面或小型接口调整，L 为跨前后端及数据规则。以下未提供工期承诺；负责人、日期在实际排期时填写。

所有项目初始状态均为“候选”。涉及 D-01 至 D-09 的原规则变更，先确认相应决策；无依赖的明确体验修复可单独推进。实施后必须记录提交、测试范围和未覆盖项，不能仅以截图打勾。

## 3. 分阶段交付与验收

### R-01｜手机搜索与详情首屏

用户故事：我从外部链接进入作品资料，也能确认目标并马上查下一条。

交付：全站手机搜索入口；详情先身份再图片；复制番号；从搜索返回原结果的路径。主要修改[页头](../apps/display-web/components/site-header.tsx)、[作品详情](../apps/display-web/app/works/[slug]/page.tsx)、[人物详情](../apps/display-web/app/performers/[slug]/page.tsx)与样式。

验收：390 × 844 下有图/缺图都能看见目标身份和搜索入口；长标题不遮挡操作；复制成功与失败都有提示；从外部进入时返回入口有效；键盘可完成搜索；320 px 普通内容不产生整页横向滚动。布局检查使用代表性内容，不能只测一条短标题。

### R-02｜账号任务续接

用户故事：我为了收藏或关注而登录，登录后能接着完成刚才的动作。

交付：明确的游客收藏/关注入口、登录与注册共享站内返回目标、可解释的动作续接状态。修改[账号请求工具](../apps/display-web/lib/auth-client.ts)及相关表单和操作组件。

验收：登录、注册、重置切换保留对象；取消不改收藏；失败可重试；目标下架有说明；仅接受安全站内路径，拒绝外站和协议相对地址；重复续接不重复创建关系。登录不是自动执行纠错、隐藏或关闭账号的授权。

风险：增加动作续接时不能把会话信息写入公开缓存，不能在 URL 中携带邮箱、密码或表单正文。

### R-03｜说明入口与历史策略

第一步交付完整公开隐私说明、使用/资料说明和联系入口，并接入注册、历史、设置、关闭账号。准确描述当前行为；如策略仍未定稿，在开放真实注册前完成定稿。

第二步在 D-03 确认后再实施历史记录开关、默认值及保留调整，覆盖服务端写入与归档。修改入口包括[设置页](../apps/display-web/app/account/settings/page.tsx)、[历史页](../apps/display-web/app/account/history/page.tsx)、[历史写入处理](../services/platform-api/internal/httpapi/account_handlers.go)。

验收：退出登录仍可阅读完整说明；注册前可达；说明与真实写入/清除行为一致。若新增暂停记录，验证暂停后所有详情类型不再追加个人历史、恢复后按决定执行；旧记录处理和老账号迁移有记录。若调整删除或保留，另验收归档、恢复与备份边界，不能让恢复复活已处理记录。

### R-04｜公开可信信息

交付：可公开来源摘要、核验日期、字段状态与纠错入口；先扩展合约源文件和 Go 公开 DTO，再生成类型和展示。不要直接手改[生成的类型](../packages/api-contracts/src/generated.ts)作为接口实现。

验收：抽样资料能从公开字段对应到内部证据；缺失或过期信息准确表达；无内部操作者身份、私人邮箱、私有 URL；有核验时间才展示核验时间；不可公开 URL 仍可显示允许公开的来源类型。隐藏/下架后对应信息不能残留在公开详情、搜索或缓存中。

依赖：D-07。需要单独核对旧数据是否有足够证据，缺证据时显示准确状态或回运营补齐，不生成虚假来源。

### R-05｜首页与广告

交付：按选定主任务组织首页；内容不足时收敛区块；账号更新按状态出现；访客广告占位策略可控；用户文案取代内部说明。

验收：空目录只有一组可执行空状态；无统计时不冒充热门；少量内容不重复堆满多个区块；首屏不被未售广告占位挡住；若采纳 D-02，普通访客在首页、详情和账号页均看不到测试占位，设计预览仍可检查位置。已有首页、广告和视觉测试随确认后的需求更新，保留“不加载联盟脚本”的边界。

依赖：D-01、D-02、R-12 的少量/丰富内容样本。客户端个性化不得导致公共 HTML 包含私人数据。

### R-06｜搜索

第一步：准确的搜索范围说明、匹配解释、无结果的下一步、输入与分页状态保存。第二步：按 D-04 增加人物/厂牌候选和类型切换，继续使用现有搜索基础。

验收：番号大小写/空格/分隔符变体、人物艺名/别名、标题、厂牌、同番号多版本、无结果和服务故障都有预期；精确匹配不被模糊项挤走；新查询不携带旧游标；分页不重复、不遗漏；下架内容不出现在任何实体结果中。合成预览的有限搜索规则不能作为真实召回率验收。

依赖：R-12 查询集。结果相关性用人工标注校验，不只追求降低零结果率。

### R-07｜关联浏览

交付：作品→厂牌链接、人物信息顺序、人物/厂牌关联作品分页、必要排序、相关理由。数据充足后再增加标签和版本关系界面。

验收：人物关联作品超过 100 条、厂牌超过 200 条仍能继续查看；总量未知时不虚构总数；日期未知不会混入“最新发行”；已隐藏偏好按 D-05 一致执行；同名人物链接准确；现有 canonical URL 与旧地址兼容策略继续有效。

### R-08｜关注更新与收藏

第一步复用现有关注作品接口，增加明确的“关注更新”入口、收藏/关注空状态引导、操作成功后的去向。第二步仅在测试支持时增加“自上次查看以来新增”的状态。

验收：没有关注、有关注无作品、有新增作品、取消关注、服务失败分别有准确呈现；补录旧作标为本站新收录，不能称作新发行；收藏后能在“我的”找到；未读状态如实现，在多设备查看、重复打开和取消关注时行为明确。

新通知状态是新增个人数据，需一起更新说明；本项不包含邮件推送和用户画像。

### R-09｜纠错闭环

交付：作品、人物、厂牌统一入口；错误字段与对象自动关联；中文状态；用户可见处理说明与修正后资料链接。

验收：必须登录的普通反馈规则保持；未登录权利渠道可达；被退回/采纳都有准确状态；内部审核理由不意外公开；提交失败保留文本，成功不同时出现错误，重复点击不产生误导。反馈采纳但修正未发布时，用户看到的进度不能宣称已完成公开更新。

服务端不抓取用户提供的 URL，不开放文件上传。两工作日响应目标需落实负责人和排班后再对外承诺。

### R-10｜偏好与异常状态

交付：统一不感兴趣的语义、加载、过滤、撤销和恢复；共享偏好读取；中文 404 和下架状态；统一空/错/缺图文案；普通列表移除排名数字。

验收：发现、搜索、最新、人物作品、厂牌作品、相关作品按 D-05 的规则逐项检查；刷新、慢网、偏好服务失败不产生互相矛盾的提示；撤销立即生效；详情下架不会仅显示“暂时没有数据”。服务错误可重试，搜索词与未提交表单不丢失。

### R-11｜运营减负

分三步：名称搜索选择人物/厂牌；可读字段差异、来源和页面预览；任务优先工作台与集中发布确认。独立暂存草稿在确认后端生命周期后另拆子任务。保留高级 JSON 查看与原受控媒体处理入口。

验收：用代表性资料完成录入不需查数据库或手填 UUID；同名候选可辨认；审核人能直接看到变化和来源；无法自己审核自己的版本；退回后能找到原因并继续；发布结果区分已提交、公开可见待确认及真实完成；严重系统故障依然可见；手机导航可以通过文字识别。

用两名承担实际职责的人员测量同一批任务，比较操作时间、错误关联和返工次数；不要通过取消异人审核缩短耗时。团队人数或职责不足时，记录运营前置条件并缩小试运行范围。

### R-12｜内容与评测基线

交付建议：约 30–50 条代表性资料与 20–30 条人工标注查询，覆盖有图/无图、别名、多版本、多人物、日期未知和长标题；另用合成扩展数据验证分页上限。数量只是起步建议，不是上线内容数量要求。

记录每条真实试运行资料的来源可用性、核心字段、核验/录入/复核耗时和维护负责人。合成内容不能用于宣称覆盖率、准确率或版权已核验。

验收：每个任务有预期答案和判定方式；查询与范围匹配；抽样准确性有独立复核；明确第一批实际维护者及另一位审核人。记录无法满足的查询类别，为后续采集连接器排序提供依据。

### R-13｜最小指标

先定义并展示已有聚合，新增统计单独评审。当前数据缺失时显示“未采集”，不能显示为 0 或已达标。

| 指标 | 定义与用途 | 数据状态/限制 |
| --- | --- | --- |
| 任务正确完成率 | 测试中正确完成的任务数 / 有效尝试数，按任务类别分开 | 新建研究记录；小样本不外推市场 |
| 完成耗时 | 从开始任务到正确确认目标，失败单独报告 | 新建研究记录；不以仅成功样本掩盖失败 |
| 零结果率 | 成功返回的首个结果页中，零结果请求 / 搜索请求 | 已有小时聚合；不包含服务错误，不是用户去重 |
| 搜索服务失败 | 搜索服务失败请求及比例，单独观测 | 需核对现有监控维度；不能混入零结果 |
| 账号有效使用 | 周内发生收藏或关注操作的账号数及净变化 | 登录数据候选，统计实现与用途待确认 |
| 关注更新使用 | 打开更新后查看关联资料的情况 | 尚未形成可用口径，不能默认有跨页归因 |
| 资料质量 | 抽样字段准确性、来源可追溯性、重复实体 | 需要定义样本、分母和复核方法 |
| 运营成本 | 每条发布资料的收集/核验/录入/审核时间与返工 | 人工记录起步，按相同任务比较 |
| 响应与积压 | 首次响应时长、临近期限数量、最老未处理任务 | 核对状态时间后计算，不能用创建数代替 |

结果点击率继续遵守原规划的“口径尚未确认”状态。若以后统计，可先讨论无查询词、无用户标识的小时级点击事件；这种点击数与搜索请求数之比并不是唯一用户转化率，也可能因重复点击超过 100%。不为得到漂亮漏斗而新增匿名指纹、长期标识或逐条搜索历史。

验收：口径文档列出分子、分母、时间窗、错误/分页/重复的处理及隐私字段；已有首屏统计不把翻页重复纳入；报表区分观测值、目标值、未采集。测试任务成功率与线上请求指标分别展示。

### R-14｜后续进入条件

自动采集：目标范围存在真实需求，人工核验方法可复用，来源可持续，审核积压可控；先自动化稳定重复的部分，继续人工发布。

商业化：有持续查询或回访证据、真实维护与运行成本、有能力完成目标环境与相关平台核对，再提一个可回退的位置实验。观察任务成功、性能、反馈和净收益。没有以上证据时本项保持候选，不承诺广告收益或会员付费。

### R-15｜索引、canonical 与 HTTP

交付：先定位预览 robots/子 sitemap 的 500；确认正式域名与环境保护；统一绝对 canonical、OG URL、JSON-LD 与 sitemap 的主地址；解决搜索 robots/noindex 冲突、厂牌分页全部归并第一页、非法参数及暂时故障的响应规则。

验收：最终入口 robots 和 sitemap 可读；预览环境继续受保护；search 的 noindex 可被读取，账号页仍需权限；合法第二页有准确自引用而非第一页 canonical；HTTP→HTTPS、旧址 301 无环路；不存在为真实 404，故障注入得到预期 503 和缓存行为。下架后详情、关联页、搜索、sitemap 与缓存同步撤下。预览发现不能直接当作正式部署根因。

### R-16｜落地内容与内部链接

交付：作品、人物、厂牌的 title/description 模板；来源摘要、别名解释、面包屑、厂牌链接与相关资料入口；有限的查询集与专题准入规则。

验收：长标题、日期未知、同名人物和多版本样本的元信息准确；正文与标题不承诺不存在的播放/下载；初始 HTML 包含核心字段与公开链接；实体有真实站内发现路径；没有只替换词语的批量落地页。缺字段时不编造信息，字数和图片数量不作为唯一质量门槛。

### R-17｜地图、分页、图片与 Schema

交付：根据真实容量分实体/分片 sitemap，避免 50,000 条硬截断并检查未压缩大小；真实 lastmod 与索引资格过滤；稳定可抓取分页；经允许的图片 SEO；保持三类实体语义，新增匹配可见导航的 BreadcrumbList。

验收：大样本地图完整、分片无漏重、每片满足 50,000 URL 与 50 MB 未压缩上限；loc 均为允许索引的有效主地址，noindex、重定向和下架页不混入；更新时间反映真实重要更新；关闭 JS 仍有可抓取 href；图片保护、默认图与权利下架不被 SEO 绕过。JSON-LD 可解析且与可见内容相符，不把语义验证通过宣称为富结果保证。

### R-18｜成人内容与搜索预览

交付：根据实际文本和图片记录内容分类、适用成人标记、搜索/分享缩略图与结构化数据展示规则；测试站保护维持原样。

验收：适用的成人内容按目标引擎官方要求标记，普通资料不凭“18+”字样随意一刀切；原有年龄限制与权利审核不因抓取而取消；不对爬虫和用户提供实质不同正文；没有虚构 VideoObject、评分或不符合资格的富结果承诺。未经确认的图片不进入搜索提交。

### R-19｜SEO 效果与 Core Web Vitals

交付：正式站点负责人配置搜索工具与 sitemap 提交；以实体类型、引擎、地区和设备划分的展示、点击、CTR、索引异常基线；补 INP 及实际用户第 75 百分位的页面体验观察。

验收：有明确工具权限与数据口径；无工具/流量数据时显示未采集或不足；有效收录分母是符合资格的主地址，不能用提交数冒充收录数。实际 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 作为目标，实验室和实测证据分列。不新增匿名指纹或逐条敏感搜索历史来补完整归因。

### R-20｜SEO 维护与发布门禁

交付：把正式域名、meta、HTTP、canonical、机器人规则、地图、公开正文和 JSON-LD 的样本检查加入发布验收；维护孤立页、坏链、来源过期、重定向及下架清单；记录每次标题、模板和索引规则变更。

验收：关键发布和下架场景有证据；异常有负责人和回退方式；分清技术错误、内容价值不足与工具延迟，避免用批量改标题或补垃圾内容应对短期波动。搜索工具提交、robots 改动及真实域名迁移均按后续明确的实施范围进行，本轮只补方案。
